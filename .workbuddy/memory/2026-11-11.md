# 2026-11-11

## 修复：买房后简历仍显示"桥洞风水宝地"

- **根因**：`core/gamedata.py` 的 `house()` 把入参当**列表下标** `hs[i]` 用，而买房 `buy_house` 写入的是 `owned_house_index()` 返回的**自购房 `i` 字段值**（当前=7）。两者只在 houses.json 的 `i` 从 0 连续递增时等价。一旦 houses.json 被编辑（i 不连续/顺序乱），`house(7)` 当下标就会错位，甚至越界钳到 0=桥洞。
- **修复**：`house()` 改为按 `i` 字段精确匹配（`for h in hs: if int(h["i"])==i`），与 `owned_house_index()` 返回值严格对齐；找不到时钳到首尾档而非静默回退桥洞。
- **关键验证**：在原始 houses.json 下，旧/新 `house()` 都返回"自购小窝"（i=7 与列表下标一致），故本次修复**不改变原始数据下的行为**。
- **推论**：用户报"桥洞"在原始数据+源码下不应发生 → 实际运行环境要么 (a) houses.json 被改过导致 i≠下标（本次修复正好对症），要么 (b) DB 里该玩家 `house` 列实际=0（买房未落库/被房租降级等改回）。需用户在 Docker 里查 DB 实际值确认。
